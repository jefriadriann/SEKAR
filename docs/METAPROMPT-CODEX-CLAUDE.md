# Metaprompt pembangunan SEKAR

Anda adalah engineer full-stack dan product designer. Bangun aplikasi web SEKAR (Sistem Informasi Evaluasi Kepatuhan, Audit & Risiko) untuk demonstrasi dengan DATA DUMMY SAJA. Implementasikan sampai aplikasi bisa dijalankan, bukan hanya menjelaskan rencana.

## Konteks dan input
Paket ini berisi sekar-dummy.json, DATA-DICTIONARY.md, README.md dan metaprompt ini. Cari file dalam folder proyek aktif. Jangan mencari atau meminta data audit asli. Semua 46 KPw dalam dataset adalah kantor FIKTIF; jangan menganggap daftar ini sebagai daftar resmi. Pertahankan unit DR terpisah. Jika PDF Pelaksanaan Tugas KPSD.pdf turut tersedia, gunakan hanya slide 19–24 sebagai referensi visual. Jika PDF tidak tersedia, spesifikasi di bawah sudah cukup untuk mulai; jangan berhenti meminta PDF.

Stack tujuan: Next.js App Router + TypeScript + Tailwind CSS + Recharts + Lucide, GitHub untuk kode, Vercel untuk hosting, Supabase untuk backend opsional. Ikuti AGENTS.md dan konvensi repo jika ada. Pada repo baru gunakan versi stabil yang kompatibel dan lockfile; periksa dokumentasi resmi saat diperlukan. Pada repo lama periksa struktur dulu dan jangan menimpa aplikasi lain. Jika repo ternyata Ruang Risiko, buat SEKAR di direktori terpisah tanpa mengubah Ruang Risiko. Jangan mengganti provider ke layanan lain.

## Hasil wajib
1. Aplikasi demo lengkap, langsung berjalan TANPA akun Supabase, token, atau environment secrets.
2. Adapter data bertipe: antarmuka repository dengan implementasi lokal dummy dan implementasi Supabase opsional. APP_DATA_MODE=dummy secara default. Pisahkan transformasi/chart dari UI. Dataset berasal dari JSON, bukan angka hardcoded di kartu atau chart.
3. Dokumentasi menjalankan lokal, build, GitHub web dan Vercel untuk pengguna non-developer; .env.example tanpa nilai rahasia; SQL migration dan petunjuk seed untuk Supabase opsional. Jangan mengklaim Supabase aktif sebelum dikonfigurasi dan diuji.

## Visual
Gaya institusional modern, biru muda dominan, navy untuk teks, gradien lembut cyan-blue dan aksen teal/amber/violet. Header konsisten bertuliskan BANK INDONESIA | DEPARTEMEN REGIONAL dan SEKAR. Gunakan placeholder identitas bertuliskan teks, bukan logo resmi hasil fabrikasi. Ilustrasi abstrak Indonesia/gedung hanya dekorasi; jangan membuat peta seolah data geografis asli tersedia. Beranda hero lapang dan empat kartu besar dua kolom. Halaman dashboard lebih padat, kartu KPI, chart, tabel dan panel panduan. Typography Calibri jika tersedia, fallback Arial/sans-serif; gunakan ukuran terbaca, whitespace terukur, hover halus, border tipis. Hindari halaman putih kosong, efek berlebihan, dan emoji sebagai ikon. Responsif desktop 1440/1366, tablet dan mobile; tabel boleh scroll horizontal dalam container. Aksesibilitas: label, fokus keyboard, kontras, chart dengan ringkasan teks, modal dapat ditutup dengan Escape.

## Navigasi dan halaman
/ : beranda dengan empat kartu Hasil Pemeriksaan KPwDN, Tracker Permindok, Jadwal Pemeriksaan, SGo dan Ketentuan. Navigasi persisten, breadcrumb, indikator Mode Demo — Data Simulasi. Persona demo DR/KPw/Admin terlihat jelas sebagai simulasi, bukan autentikasi nyata.
/hasil-pemeriksaan : filter tahun (termasuk Semua Tahun), pemeriksa BPK/DAI/KAA, korwil, KPw dan area. Chart jumlah temuan per area, sebaran korwil berupa bar, tren tahunan, proporsi per pemeriksa. Klik kategori chart memfilter tabel dan menyediakan reset. Tabel temuan dengan rekomendasi, status, tenggat, PIC, jumlah kantor terdampak jika memakai agregasi tema. Drilldown membuka detail dan bukti terkait. Pisahkan menghitung jumlah temuan dari jumlah KPw unik. Jangan memasukkan temuan unit DR ke agregasi KPw. Sediakan panel rekonsiliasi aset dari asset_reconciliations dan panel materi pembelajaran.
/permindok : filter tahun/jadwal/kategori/KPw/status, search, panel catatan pemenuhan, panduan watermark dan tanda terima (materi simulasi), chart status per kategori, tabel tanggal permintaan/tenggat/penyampaian/catatan DR/status. Bedakan status kelengkapan dari ketepatan waktu. Detail dapat diedit dalam demo dan perubahan tersimpan lokal.
/jadwal-pemeriksaan : timeline/Gantt dari audit_schedules, tampilan bulan/kuartal/tahun, garis Hari Ini, KPI total/berlangsung/mulai dalam 7 hari/mendatang/selesai. Tanggal belum terkonfirmasi harus diberi label Tentatif. Panel pemeriksaan terdekat dan tabel tindak lanjut temuan dengan tenggat, status dan bukti. Status jadwal dihitung dari tanggal, jangan memakai badge random.
/sgo-ketentuan : kartu Apa itu SGo dan tutorial, grid delapan area sesuai dataset, tombol worksheet dan ketentuan, pencarian materi, drawer/preview materi. Materi semuanya berlabel simulasi; jangan mengarang nomor PDG/PADG/SOP resmi atau memasukkan video eksternal yang tidak relevan.
/dr : dashboard khusus Departemen Regional. KPI 24 temuan DR dengan 16 selesai, 6 dalam proses, 2 belum ditindaklanjuti DIHITUNG dari dataset. Tabel pemeriksaan DR dengan filter BPK/DAI/KAA, data kepatuhan DR, permindok DR, dokumen penting dan ketentuan kelompok. DR dapat membuka overview KPw, tetapi data audit DR tidak pernah muncul dalam modul KPw.
/admin : hanya persona admin demo; import JSON dengan preview, validasi struktur/foreign key/status/tanggal, konfirmasi penggantian dataset, export JSON dan reset ke seed awal. Tolak data tidak valid tanpa merusak dataset aktif. Perlihatkan tanggal dataset dan sumber simulasi.

## Interaksi dan aturan data
Semua tombol bekerja: navigasi, filter, reset, sorting, pagination, pencarian, drawer detail, preview/unduh dokumen simulasi, edit status dan export. Buat bukti simulasi sebagai file .txt dari content_text; jangan memalsukan tautan PDF yang 404. Tutorial tanpa video sungguhan tampil sebagai panduan langkah demi langkah, bukan tombol play mati. Untuk export CSV jika ditambahkan, escape formula injection, quotation, koma dan newline. Simpan perubahan DEMO di localStorage dengan namespace/version dan reset; dataset JSON asli tidak diubah. Tidak ada upload ke server pada mode dummy. Loading, error, empty state dan not-found harus jelas.
Gunakan metadata.as_of sebagai tanggal acuan default demo (5 Oktober 2026), supaya hasil konsisten; tampilkan tanggal itu dan sediakan kontrol tanggal simulasi. Semua KPI/chart/tabel harus mempergunakan filter yang konsisten; tren dapat membandingkan semua tahun tetapi jelaskan cakupannya. Persentase menangani denominator nol. Update status selesai mengisi completed_at, membuka kembali mengosongkannya. Validasi tanggal penyampaian tidak mendahului permintaan.

## Akses: demo dan backend harus berbeda
Persona DR: overview semua KPw plus modul DR; persona KPw: data kpw-01 saja dan materi shared, tanpa route/data DR; admin: seluruh data dan import. Di demo, dataset tetap bisa diperiksa oleh pengguna browser: ini hanya simulasi UX, bukan proteksi confidentiality. Jangan menyebut demo login sebagai keamanan produksi.
Supabase opsional: Auth sungguhan; roles dan unit assignment disimpan dalam tabel yang tidak dapat diedit oleh pengguna biasa; RLS setiap tabel membatasi SELECT/INSERT/UPDATE/DELETE sesuai role dan unit, termasuk documents dan references. Jangan memakai metadata role yang bisa diubah pengguna sendiri. Route/API memvalidasi session dan peran, bukan mengandalkan hidden menu. Storage bucket privat; dokumen DR khusus DR/admin; akses dokumen KPw sesuai unit; signed URL hanya setelah otorisasi. Secret/service-role key tidak boleh ada di browser atau NEXT_PUBLIC. Signup tidak otomatis mendapat akses; default akun baru tidak berwenang sampai dipetakan admin. SQL seed tidak menciptakan akun Auth atau password bawaan; jelaskan mapping setelah akun tersedia. Tidak ada fallback ke dummy diam-diam jika mode Supabase gagal: tampilkan error konfigurasi. Jangan deploy, push atau membuat resource cloud tanpa instruksi berikutnya. Tidak ada data audit riil pada demo atau seed.

## Pelaksanaan dan verifikasi
Inspeksi repo, buat ringkasan rencana singkat lalu kerjakan. Ambil keputusan rutin sendiri. Jangan berhenti karena credentials/PDF tidak tersedia; mode dummy tetap harus selesai. Buat data dictionary/types, implementasikan seluruh route dan backend opsional, jalankan typecheck/lint/build. Tambahkan pengujian bermakna untuk agregasi, scope DR/KPw, status tanggal, import invalid dan perubahan status; jika Supabase belum tersedia, jelaskan RLS integration belum diuji. Gunakan browser/Playwright bila tersedia untuk smoke test seluruh halaman, filter, drawer, edit, import/reset dan ukuran layar; perbaiki overflow/error console. Jangan mengklaim pengujian yang belum dijalankan. Pada akhir berikan cara npm install/npm run dev dan daftar hasil cek, batasan demo, serta langkah Vercel/Supabase. Hasilnya harus aplikasi terintegrasi yang dapat dipakai, bukan screenshot dashboard atau landing page saja.
